## 바꾼 동작

기존 refreshRecording은 조회 중이면 다음 조회를 예약하고 반환했다. 화면이 오래 멈췄다가 돌아와도 이전 fetch가 끝날 때까지 새 조회를 시작하지 못하므로, 기존45초 제한시간까지 기다릴 수 있었다.

명단 조회마다 시작 시각과 전용 취소 신호를 보관한다. 화면 복귀·bfcache 복원·온라인 복귀 때15초 이상 된 진행 중 명단 조회만 중단하고 교체한다. 이전 조회의 늦은 응답·실패·로그인 오류가 현재 화면을 덮어쓰지 못하도록 기존 readEpoch와 함께 확인한다. 짧은 전환은 현재 요청을 유지한다.

체크 저장 요청에는 외부 취소 신호를 연결하지 않는다. 기기에 보관한 SENT/QUEUED 입력, 저장 requestId, 학생별 revision, 저장 후 서버 재확인과 재시작 복구는 유지한다. 저장 중에는 새 조회를 미루고 저장이 끝난 뒤 확인한다.

15초는 서버 처리속도 보장이나 휴대전화 잠금 시간 조건이 아니다. 복귀 시 진행 중인 조회를 오래된 요청으로 판정하는 기준이다.

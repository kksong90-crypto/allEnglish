# 잠금 직전 후속 묶음 전송 · UI8.2.27

## 문제·선택

기존 전송 큐는 첫 묶음 응답 후에 다음 묶음을 보낸다. 연속 체크 중 화면이 멈추면 첫 요청이 서버에서 끝나도 브라우저 응답 처리가 재개되기 전에는 뒤의 체크가 전송되지 않을 수 있다. 이 대기를 줄이기 위해 화면 숨김/pagehide에서 최대2개 요청을 전송한다. 평소 전송은 계속 직렬이다.

각 요청은 최대30명이며 세션·날짜·검증 상태를 다시 확인한다. 서버 ScriptLock과 학생별 revision/CAS는 유지한다.61건 이상 또는 본문 유지 예산 초과, 화면이 이미 정지한 경우까지 백그라운드 완료를 보장하지 않는다. 단건 서버 저장 속도를 줄인 변경도 아니다.

## 응답 순서와 복구

겹친 두 요청은 독립된 학생별 저장 결과만 적용하고, 이전 응답의 전체 집계/공지를 그대로 덮지 않는다. 모두 끝나면 최신 서버 자료를 한 번 재조회한다. 응답 순서가 뒤바뀌어도 집계가 되돌아가지 않도록 검사했다. 저장 ACK가 있는데 집계 재조회만 실패한 경우에는 저장 완료·집계 확인 대기로 구분한다. 저장 여부를 모르는 실패와 섞지 않는다.

잠금 해제의 visibilitychange뿐 아니라 focus·브라우저 resume에서도 기존 복귀 처리를 호출한다. 저장 요청을 취소하거나 중복 보관 항목을 자동으로 덮지 않는다.

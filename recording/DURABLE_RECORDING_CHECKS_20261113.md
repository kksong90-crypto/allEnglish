## 저장과 복구 동작

일반 체크를 누르면 네트워크 요청보다 먼저 localStorage의 개별 요청 키에 보관하고 실제 저장 여부를 다시 읽어 확인한다. 보관에 실패하면 전송하지 않으며 미저장 안내를 한다. 한 배열을 덮어쓰지 않아 다른 탭의 별도 체크가 지워지지 않는다. 보관 값은 날짜·반/학생 ID·희망 상태·요청 번호·기존 변경 버전·API·로그인 소유 범위 등으로 제한한다. 학생 이름·PIN·전체 인증 토큰/서명을 새로 복제하지 않는다.

앱이 다시 열리거나 연결이 복구되면 보관 목록이 있는 경우 캐시를 우회해 서버 상태를 먼저 읽는다. 최근 화면 미리보기나 실패한 조회 결과로 복구하지 않는다.

| 서버에서 확인한 조건 | 처리 |
|---|---|
| 이미 원하는 상태 | 재저장하지 않고 해당 보관 항목만 정리 |
| 같은 API·로그인·날짜, 기존 변경 버전 일치, 현재 체크 가능 | 원래 요청 번호와 변경 버전으로 순차 복구 |
| 새 로그인·다른 기기 변경·결석·마감·버전 누락 | 자동 전송하지 않고 보관 및 확인 버튼 표시 |
| 다른 날짜 | 해당 날짜를 확인하는 버튼, 자동으로 현재 학생에 적용하지 않음 |
| 동일 학생의 서로 다른 보관 항목 | 확인 대상으로 고정, 한 항목 정리 후 나머지를 자동 전송하지 않음 |
| 통신 결과 미확정 | 같은 화면에서 무한 재시도하지 않음. 서버 재조회 후 보관 유지 |
| 손상된 보관 정보 | 전송 제외·경고. 다른 앱의 저장 정보를 건드리지 않음 |

복구 요청의 성공 응답이 예전에 캐시된 응답일 수 있으므로 그대로 화면에 적용하지 않고 다시 서버를 읽는다. 서버의 잠금 내부 expectedRevision 비교는 계속 유지한다. 서버 요청 캐시는 6시간의 최선형 캐시이며 영구 중복방지 수단으로 가정하지 않는다.

보관 취소는 기기에 남은 요청만 정리한다. 서버 값을 변경하지 않는다. 변경 확인 후 다시 저장하는 수동 동작은 새 요청 번호와 방금 읽은 서버 버전을 사용하며 확인 창을 거친다.

## 제한과 다음 단계

실제 휴대전화의 OS 강제 종료·장시간 화면 잠금·브라우저 저장 정책·홈 화면 설치 앱에서의 검증은 아직 하지 않았다. 이번 실증은 인증된 브라우저에서 실제 네트워크 저장 중 페이지를 새로고침하여 자바스크립트 메모리를 폐기한 검증이다. 로컬 저장 데이터 자체가 지워지거나 다른 출처/브라우저로 이동하면 기기의 보관 목록을 복원할 수 없다.

오프라인에서 새로운 체크 입력을 여는 기능은 추가하지 않았다. 마감 전 예외 인정, 예정결석, 학교시험 저장은 이번 보관 대상이 아니다. 화면에 표시된 제출 합계는 계속 서버 확정값이다. 초기 조회·저장의 실제 지연은 여전히 길며 ‘속도 문제 해결’로 집계하지 않는다. 활성 공지 시간창, 별도 운영센터 재조회, 휴대전화 실기기 테스트 및 운영 전환은 통합 승인 기준에 남긴다.

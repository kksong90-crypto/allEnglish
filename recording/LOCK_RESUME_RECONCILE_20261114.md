# 잠금 복귀 후 저장 확인 표시 수정 (2026-11-14)

사용자가 실제 휴대전화 잠금 해제 후 저장 중→확인 필요 전환을 보고했다. 이후 클라우드에서 서버 재조회한 검증학생1은 체크 해제 상태로1/2였으므로 해당 해제는 서버에 반영됐다. 사용자 기기에 경고가 계속 남았는지는 미확인이다. 실물 OS 종료 전체 검증을 통과로 집계하지 않는다.

원인: 복구 재전송의 정상 응답도 최신 조회로 재확인하도록 만든 기존 보호 경로가 재조회 시작 전에 확인 필요를 표시했다. 또한 재조회 성공이면 보관 입력과 다른 서버 값도 서버 상태 재확인 완료로 표시해 실제 검토 필요 상태를 가릴 수 있었다.

수정: 자동 재조회 중에는 저장 결과 확인 중(saving), 실제 최신 값이 보관한 의도와 일치하고 기기 보관 정리도 성공해야 저장 확인 완료다. 최신 값이 다르거나 조회 실패이면 확인 필요를 유지한다. 재전송/CAS/학생별 범위/최신 상태 보호/보관 취소 확인은 바꾸지 않았다. 읽기 대기 도중의 표시를 멈춰 확인하는 검사, 더 최신인 다른 값 유지, 재조회 실패 시 보관 유지의3검사를 추가해 화면138/138 통과.

새 격리 UI8.2.25-RECONCILE-STATE. 서버 Code와 연결·인증 bootstrap은 동일하다. 배포 후 실제 확인 결과는 추가 기록한다.

# 단어장·개인 시험 사용성 리뷰와 반영 결과

> 후속 상태: 학생웹 개선은 PR60으로 기존 실사용 주소에 반영됐고 Pages·게시 확인·Chromium/WebKit·37개 모듈·배포본 합성 성능 검사가 통과했다. 아래 개발/리뷰 시점의 미배포 기록과 구분한다. 실제 계정 첫 조회 속도는 미측정이다. [최종 영수증](VOCAB_ROLLOUT_20261116.md).

## 리뷰의 성격

사용자의 실제 피드백(검색이 느림, 관리자 카드 기능을 찾기 어려움, 다른 단어를 선택해야만 학습 방식으로 돌아갈 수 있음)을 기준으로 4개 에이전트가 학생·관리자/교사·검색 오류·모바일 상황을 독립 검토했다. 발견 사항은 재현 테스트를 먼저 작성하고, 주 에이전트가 제품 코드를 수정한 뒤 원 리뷰 담당자가 다시 검증했다.

**실제 학생/교사 인터뷰나 사용자 만족도 조사가 아니다.** 아래 경험은 코드 실행, 가상 계정·API, 실제 Chromium 렌더링으로 재현한 시나리오 결과다. 운영 계정의 응답시간이나 실제 스크린리더 음성을 검증한 것으로 해석하지 않는다.

기준 후보는 로컬 `feature/vocab-search-practice-20261116`, 리뷰 시작 기준 `998f19d`다. 원격 게시/운영 배포는 하지 않았다.

- 실제 렌더링·키보드 리뷰: [mobile-review.browser.mjs](../browser-tests/mobile-review.browser.mjs)

24개의 새 시나리오 및 기존 검사를 포함한 **35개 portable 테스트 모듈 통과**. 전체 JavaScript 구문 검사와 `git diff --check` 통과.

기존 Chromium 브라우저 검사도 통과: 320/390/1365px 배정 연습 4모드·중복 계획 차단, 학생·관리자의 같은 3개 폭 공개 교재 검색/카드/복귀. 모바일 키보드 검사를 기존 CI 브라우저 작업에 추가했다. 이 CI 변경은 로컬 후보이며 원격 실행 결과로 주장하지 않는다.

## 실제 사용자의 다음 확인 항목

실제 피드백을 받을 때는 별점·만족도 수치를 만들어 넣지 말고, 역할/기기/과제/완료 여부/막힌 단계/관찰 내용/수정 후 재확인을 기록한다. 학생 개인정보나 비밀번호를 기록하지 않는다.

1. 실제 학생이 자신의 교재·범위를 찾아 카드를 시작하고, 뜻을 가렸다 보며 모드를 바꾸고 원래 범위로 돌아갈 수 있는가.
2. 실제 관리자·교사가 같은 교재/범위에서 미리보기를 찾고 오답 재시험까지 검수할 수 있는가.
3. 실제 휴대폰 가상 키보드·뒤로가기·스크린리더에서도 입력/복귀가 이어지는가.
4. 운영 계정의 최초 목록/범위/전체 검색/반복 검색 시간을 각각 측정할 것. 합성 API 결과를 운영 속도로 사용하지 않는다.

VocabDB 최신 이관 상태·서버 병목 및 운영 반영은 이전 요청의 남은 작업이다. 앞선 원격 게시 자동 승인 거절 뒤 명시적 게시/운영 승인을 받지 않았으므로 이번 에이전트 리뷰에서 원격 게시·CI 실행·실사용 배포를 시도하지 않았다.

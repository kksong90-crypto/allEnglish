# 단어장 빈 응답·중요단어 직접 진입 복구 후보

기준: 학생웹 main `dc35a8d`. 별도 작업 브랜치의 프론트 후보이며 운영 배포 전이다. 실제 학생 로그인은 사용하지 않았고, 사용자가 보고한 오류의 출처를 이 두 UI 결함으로 단정하지 않는다.

## 확인한 결함과 최소 수정

1. 정규 단어장 읽기의 header-only/빈 응답, 이름 없는 책 목록이 `true`를 반환해 `vocabLoadedOnce`에 성공으로 남았다. 이전 선택·검색 결과도 남을 수 있었다. 내부 시트명 대신 일반 안내와 다시 불러오기 버튼을 제공하고, 읽기를 실패 상태로 반환하며 오래된 선택·결과를 제거한다. 정상 목록이 있는 경우의 성공 캐시는 유지한다.
2. 중요단어를 저장한 상태로 처음 중요단어 탭에 들어가면 아직 단어 행을 읽지 않았다는 이유로 빈 폴더처럼 표시했다. 저장 키가 있는 경우에만 기존 정규 단어장 읽기를 기다린 후 표시·시험·뜻 확인을 실행한다. 저장 키가 없으면 전체 단어 읽기를 하지 않는다.

중요단어 읽기는 로그인 epoch·token, 현재 폴더·키 목록, 활성 탭, 최신 요청을 확인한다. 실패하면 보이는 중요단어 화면에서 다시 불러올 수 있다. 일부 저장 키를 현재 목록에서 확인하지 못했을 때는 키를 삭제하거나 부분 시험을 조용히 시작하지 않는다. 기존 명시적 native pilot의 전용 본문·중요단어 경로는 바꾸거나 기본 활성화하지 않는다.

## 사용자 오류와의 경계

사용자가 나중에 제공한 정확한 메시지 ‘전체 시험범위 응답을 확인할 수 없습니다. 처음부터 다시 시작하세요.’는 배정 전체 범위의 서버 응답 검증 경로다. 이 후보는 그 검증을 완화하지 않으며, 위 단어장/중요단어 문제를 해당 서버 오류의 원인 또는 해결로 표현하지 않는다.

합성 브라우저에서 같은 서버 메시지를 표시하고 연습 상태를 만들지 않는 것을 확인했다. 구형 200문항 표본과 `coverage` 없는 응답도 계속 거부한다. 서버의 실제 연결 대상·ALL 계약 문제는 별도 조사·조치 대상이다.

일반 정규 단어장은 학생 본인의 배정 범위만 보여 주는 UI가 아니다. 읽기 확인한 서버 함수는 학생/관리자에 동일한 활성 정규 책을 제공하며, 학생에게만 현재 포인트 단어가 추가될 수 있다. 이는 캡처된 서버 함수의 가상 자료 실행과 합성 역할 검증이며, 실제 계정 HTTP 호출을 통한 확인이라고 주장하지 않는다. 공개 교재는 별도 카탈로그 정책에 따라 숨김·내부 자료를 제외하고, 배정 연습은 서버 소유 계획·권한으로 검증한다.

## 검증

- 기존 39개 회귀 모듈과 새 중요단어 모듈: **40/40 통과**.
- 정규 단어장 읽기 회귀 **13/13**, 새 중요단어 읽기/경계 검사 **7/7 통과**. 저장 키 없음의 요청 0, 읽기 중 시험 시작 보호, 실패 후 회복, 폴더 전환·로그아웃·탭 이탈의 늦은 응답 차단, 미해결 키 보존, native pilot 분리를 검사한다.
- 실제 프론트+합성 계정/API의 새 역할 매트릭스: **Chromium 19/19, WebKit 19/19 통과**. 학생·관리자 진입, 공개 카테고리/범위/검색/미리보기, 정규 목록, 중요단어 첫 진입, 빈 응답·네트워크·서버 오류 후 재시도, 로그인 만료, 정확한 배정 오류와 구형 응답 거부를 포함한다.
- 기존 세 학습 경험 여정도 **각 엔진 14/14 통과**. 테스트의 공식 저장 호출은 0이다.
- 실제 학생 인증 UAT·운영 검색 지연은 이 테스트에 포함하지 않는다. 운영 쓰기·배포·main 병합은 하지 않았다.

재현 명령:

```sh
node scripts/check-student-web.mjs
node browser-tests/vocab-entry-recovery.browser.mjs chromium
node browser-tests/vocab-entry-recovery.browser.mjs webkit
node browser-tests/practice-experience.browser.mjs chromium
node browser-tests/practice-experience.browser.mjs webkit
```

CI의 기존 실제 UI job에 새 매트릭스 검사를 추가했다. native/기존 UI의 별도 fallback 검사도 유지한다. 결과 파일은 `browser-tests/artifacts/vocab-recovery/<engine>/results.json`이다.
